# 账号养号日常操作手册

本文面向实际使用者，说明新账号从导入、开始养号、每日检查，到养熟后投入业务的操作顺序。本文只描述当前系统已经支持的能力，不包含自动调度、独立代理或导入后自动养号。

## 一、基础前提

开始前确认以下条件：

- 后端已正常启动。
- 前端已经使用最新构建版本。
- `data/warming_prompts.json` 存在且内容非空，否则养号 worker 会禁用。
- 当前登录用户有号池管理权限。
- 若不是 admin 用户，需要在 RBAC 中授予以下 API 权限：
  - `GET /api/accounts/warming/status`
  - `POST /api/accounts/warming/start`
  - `POST /api/accounts/warming/stop`
  - `POST /api/accounts/update`

当前规则：

- 导入账号后不会自动进入养号。
- 只有 `warming_status = "warming"` 的账号会被养号 worker 处理。
- `warming_status = "warming"` 的账号不会参与普通业务请求。
- `warming_status = "done"` 表示已养熟，并等同于投入业务。
- 每个养号账号每天最多执行一次，依据 `warming_last_action_at` 判断。

## 二、第一天导入 10 个新账号的操作

假设第一天有 10 个新账号需要进入养号流程。

### 2.1 导入账号

任选一种导入方式：

1. 将 10 个账号 JSON 文件放入 `data/auto_import/`，然后启动服务或调用导入扫描。
2. 在前端“号池管理”页面使用导入按钮导入 Token、Session JSON 或 CPA JSON。

导入后进入“号池管理”页面确认：

- 账号总数增加。
- 新账号出现在账号列表中。
- 新账号默认是普通账号，不会自动显示“养号中”。

### 2.2 将新账号标记为养号中

推荐操作：

1. 在账号列表中通过搜索、类型、状态等条件找到这 10 个新账号。
2. 勾选这 10 个账号。
3. 点击 `设为养号中`。

系统会逐个更新这些账号：

```json
{
  "warming_status": "warming",
  "warming_day": 0
}
```

完成后，这些账号会显示为：

```text
养号中 D0
```

此时这些账号已经从普通业务调度中隔离，不会处理文本或图像业务请求。

### 2.3 启动当天养号任务

在“养号任务”控制条中：

1. 点击 `开始养号`。
2. 查看任务状态是否变为 `运行中`。
3. 查看进度，例如 `进度 0 / 10`、`进度 3 / 10`。
4. 等待任务完成，状态回到 `未运行`。

任务完成后，成功的账号通常会从：

```text
养号中 D0
```

变成：

```text
养号中 D1
```

并显示 `今日已跑`。

### 2.4 当天收尾检查

筛选 `养号中`，检查这 10 个账号：

- 大多数账号应显示 `养号中 D1`。
- 今日已经执行的账号应显示 `今日已跑`。
- 如果有失败账号，badge 可能带有失败次数。

如果某个账号失败：

- 失败 1-2 次可以先观察。
- 失败达到 3 次后，筛选 `失败 >= 3`，人工检查 token、session、代理、账号状态或网络问题。

## 三、第二天到第六天的日常操作

每天固定做一次即可，推荐放在业务低峰期。

### 3.1 筛选待养账号

进入“号池管理”：

1. 选择养号筛选 `养号中`。
2. 确认列表中还有待养账号。
3. 如果账号显示 `今日已跑`，说明当天已经执行过，重复启动不会再次处理该账号。

### 3.2 启动养号任务

点击 `开始养号`。

worker 会自动处理：

- `warming_status = "warming"`
- 且今天没有执行过的账号

每天成功一次后，`warming_day` 会增加 1。

预期变化：

| 日期 | 当天开始前 | 当天成功后 |
|------|------------|------------|
| 第 2 天 | `养号中 D1` | `养号中 D2` |
| 第 3 天 | `养号中 D2` | `养号中 D3` |
| 第 4 天 | `养号中 D3` | `养号中 D4` |
| 第 5 天 | `养号中 D4` | `养号中 D5` |
| 第 6 天 | `养号中 D5` | `养号中 D6` |

### 3.3 每日检查失败账号

每天任务结束后：

1. 筛选 `失败 >= 3`。
2. 检查失败账号是否集中在同一批、同一代理或同一账号来源。
3. 对明显异常账号执行诊断或刷新。
4. 不建议在未确认原因时直接投入业务。

`warming_errors` 表示连续养号失败次数：

- 成功一次会清零。
- 失败一次会加 1。
- 达到 3 次表示需要人工关注，不等同于账号一定不可用。

## 四、第七天养熟并投入业务

第七天开始前，账号通常显示：

```text
养号中 D6
```

当天点击 `开始养号` 后，如果账号成功完成本次养号，系统会自动将其标记为：

```text
已养熟 D7
```

当前业务规则中：

- `养号中` 会被业务调度隔离。
- `已养熟` 不再被业务调度隔离。

因此 `已养熟` 等同于已经投入业务。

## 五、批量操作建议

### 5.1 批量将新账号设为养号中

适用场景：当天导入了一批新账号。

操作：

1. 筛选或搜索出这批新账号。
2. 当前页全选，或手动勾选目标账号。
3. 点击 `设为养号中`。

结果：

- 账号变为 `养号中 D0`。
- 账号立即从业务调度中隔离。

### 5.2 批量取消养号

适用场景：

- 标记错了账号。
- 某批账号暂时不参与养号。

操作：

1. 筛选 `养号中`。
2. 勾选目标账号。
3. 点击 `取消养号`。

结果：

- `warming_status` 清空。
- 账号回到普通账号状态。

注意：取消养号后，该账号不再被 warming worker 处理。

### 5.3 批量设为已养熟

适用场景：

- 人工确认某批账号无需继续养号。
- 需要直接投入业务。

操作：

1. 勾选目标账号。
2. 点击 `设为已养熟`。

结果：

- 账号显示 `已养熟`。
- 账号可参与业务调度。

## 六、停止任务的使用方式

点击 `停止任务` 会请求 worker 停止当前养号任务。

注意：

- 当前实现是 context cancel，不承诺“当前账号完整完成后停止”。
- 如果正在等待或消费 SSE，当前账号可能被中断，并记录一次失败。
- 因此不建议频繁点击停止。

推荐只在以下场景使用：

- 发现代理或网络异常。
- 发现导入了错误账号。
- 需要立即释放资源。
- 误点了开始养号。

## 七、推荐每日流程

### 第 0 天：准备

1. 准备 `warming_prompts.json`。
2. 确认前端能看到“养号任务”控制条。
3. 确认账号导入方式可用。

### 第 1 天：导入并开始养号

1. 导入新账号。
2. 找到新账号并批量 `设为养号中`。
3. 点击 `开始养号`。
4. 任务完成后确认账号变为 `养号中 D1`。

### 第 2-6 天：每日推进

1. 筛选 `养号中`。
2. 点击 `开始养号`。
3. 等待任务结束。
4. 检查是否有 `失败 >= 3` 的账号。

### 第 7 天：养熟投入业务

1. 筛选 `养号中`。
2. 点击 `开始养号`。
3. 成功账号会自动变为 `已养熟 D7`。
4. `已养熟` 账号可参与业务调度。

### 第 8 天以后：维护

1. 定期查看 `失败 >= 3`。
2. 对异常账号进行诊断、刷新或删除。
3. 新账号继续从第 1 天流程开始。

## 八、常见问题

### 8.1 导入账号后为什么没有自动养号？

这是当前设计。导入账号不会自动设置 `warming_status`，需要人工批量 `设为养号中`，避免错误账号被自动发起外部请求。

### 8.2 点击开始养号后为什么进度是 0 / 0？

通常表示当前没有可处理账号。可能原因：

- 没有账号处于 `养号中`。
- 所有养号账号今天已经执行过。
- warming worker 未初始化，例如 `warming_prompts.json` 不存在或为空。

### 8.3 已养熟账号还需要取消养号吗？

通常不需要。当前规则中 `已养熟` 已经等同于投入业务。

如果不想保留养号标记，可以手动点击 `取消养号`，但这不是必须操作。

### 8.4 失败 3 次的账号要怎么处理？

先不要直接投入业务。建议按顺序检查：

1. 账号 token 是否有效。
2. session 是否可刷新。
3. 代理或网络是否异常。
4. ChatGPT 页面是否存在额外风控。
5. 是否是人工点击 `停止任务` 导致中断失败。

确认可用后，可以继续让它保留 `养号中`，下一次成功会自动清零失败次数。
