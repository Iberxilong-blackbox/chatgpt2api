# Retouch 页面交互流程规格

本文档定义 Retouch 页面的第一版产品目标、核心路径、页面状态、交互行为与 API 接入边界。后续实现应优先遵循本文档，再按阶段补充更复杂的历史、分支和小地图能力。

---

## 1. 产品目标

Retouch 页面是一个支持多轮局部重绘的图片编辑工作台。用户可以上传一张图片，在图片上标记需要修改的区域，输入修改要求并提交生成。每一轮生成完成后，页面以左右双栏展示本轮输入图与输出图，方便用户对比差异。

核心目标：

- 支持用户进行多轮局部重绘。
- 每一轮都清楚展示“本轮输入图”和“本轮生成图”的区别。
- 用户可以从任意已有图片继续发起下一轮重绘。
- 每张真实存在的图片都有稳定的全局序号，例如 `#1`、`#2`、`#3`。
- 失败任务不产生新图片序号。

当前阶段聚焦主路径：

- 上传图片。
- 涂鸦标记局部区域。
- 输入 prompt。
- 提交真实生成任务。
- 等待生成。
- 成功后左右对比。
- 从左图或右图中选择任意一张继续编辑。
- 下载当前展示的图片。

暂不实现：

- 复杂树状 minimap 的高级布局与动画。
- 多结果批量选择。
- 图片版本重命名。
- 多任务并发编辑。
- 复杂历史时间线动画。

## 2. 核心用户路径

主路径：

1. 用户进入 Retouch 页面。
   系统显示上传图片入口，底部 prompt 输入处于不可提交状态。

2. 用户上传一张准备编辑的图片。
   系统将该图片登记为 `#1`，进入可编辑状态，显示图片画布、涂鸦笔和 prompt 输入框。

3. 用户用涂鸦笔标记需要修改的区域。
   系统在当前图片上显示标记层，并保留用户的涂鸦内容。

4. 用户在 prompt 输入框中描述修改要求，并点击发送。
   系统进入提交/等待状态。页面切换为双栏：左侧显示本轮输入图，右侧显示等待区域。

5. 生成任务等待中。
   左侧继续显示 source image，例如 `#1`。右侧显示 spinner 和已等待时间。

6. 生成成功。
   系统为新图片分配下一个序号，例如 `#2`。页面展示左右对比：左侧为 `#1`，右侧为 `#2`。

7. 用户根据结果继续下一轮。
   如果用户不满意 `#2`，可以点击左侧 `#1`，在 `#1` 上继续涂鸦并提交。
   如果用户满意 `#2` 但想继续优化，可以点击右侧 `#2`，在 `#2` 上继续涂鸦并提交。

8. 再次提交。
   系统把当前被选中的图片作为新一轮 source image。等待时左侧显示该 source image，右侧显示 spinner 和已等待时间。成功后新结果获得下一个序号。

统一规则：

```text
用户从任意已有图片中选择一张作为 source image。
用户在 source image 上涂鸦并输入 prompt。
点击发送后创建一轮新任务。
任务成功后生成一张新 result image，并分配下一个全局序号。
```

示例：

```text
#1 上传原图
├─ #2 从 #1 第一次生成
├─ #3 从 #1 重新生成
└─ #4 从 #2 继续生成
```

第一阶段 UI 不需要完整展示树结构，但底层数据应允许未来表达这种分支关系。

## 3. 页面状态表

第一版状态保持克制，只定义主路径所需状态。

| 状态 | 进入条件 | 主区域 UI | 控制区 UI | 允许操作 | 下一状态 |
| --- | --- | --- | --- | --- | --- |
| `empty` | 没有上传图片 | 上传入口 | prompt 可输入但不可发送，或整体弱化 | 上传图片 | `editing` |
| `editing` | 已有 source image，用户正在准备修改 | 当前 source image，可涂鸦 | prompt 可输入，发送可用 | 涂鸦、修改 prompt、发送、移除图片 | `submitting` |
| `submitting` | 用户点击发送，正在创建任务 | 双栏：左侧 source image，右侧提交中 | prompt 禁用，发送按钮 loading | 等待、取消 | `polling` / `error` |
| `polling` | 任务已创建，等待结果 | 双栏：左侧 source image，右侧 spinner + 已等待时间 | prompt 禁用，发送按钮 loading | 等待、取消 | `success_split` / `error` |
| `success_split` | 任务成功，result image 已生成 | 双栏：source image + result image | prompt 可用，但需先选中图片才可发送 | 选择左图/右图、下载图片、继续编辑 | `editing` / `submitting` |
| `error` | 提交失败或生成失败 | 双栏：左侧 source image，右侧错误信息 | 保留 prompt 和涂鸦，显示重试 | 重试、取消、修改 prompt | `submitting` / `editing` |

建议状态字段：

```text
imagesById: Record<string, RetouchImage>
imageOrder: string[]
currentSourceImageId: string | null
currentResultImageId: string | null
selectedSourceImageId: string | null
activeTurnId: string | null
pageStatus: "empty" | "editing" | "submitting" | "polling" | "success_split" | "error"
```

说明：

- `currentSourceImageId` 表示当前左右对比中的左图。
- `currentResultImageId` 表示当前左右对比中的右图。
- `selectedSourceImageId` 表示用户当前选中并准备继续编辑的图片。
- 初次上传的图片编号为 `#1`。
- 只有生成成功的新图片才获得新编号。

## 4. 每个状态的 UI 布局

### `empty`

布局目标：

让用户明确第一步是上传图片。

主区域：

- 居中大尺寸上传区域。
- 支持点击选择文件和拖拽上传。
- 上传区域不承载过多说明文字，保持工具型页面的直接感。

控制区：

- 底部 prompt 输入框可以显示，但发送按钮禁用。
- 也可以弱化底部输入，让视觉焦点集中在上传入口。

### `editing`

布局目标：

让用户专注于当前 source image 的局部标记和 prompt 输入。

主区域：

- 显示当前被编辑图片。
- 图片上方叠加涂鸦层。
- 图片角落显示编号，例如 `#1`。
- 如果来自双图状态的点击选择，选中图片应有明确强调。

控制区：

- 底部 prompt 输入框固定在页面下方。
- 发送按钮在有图片且 prompt 非空时可用。

### `submitting` / `polling`

布局目标：

用户应立刻知道任务已经开始，并能看到本轮正在使用哪张 source image。

主区域：

- 左侧显示 source image 和编号。
- 右侧显示等待区域。
- `submitting` 可显示“正在提交”。
- `polling` 显示 spinner 和已等待时间，例如 `00:18`。

控制区：

- prompt 输入框禁用。
- 发送按钮显示 loading。
- 可保留取消入口。

### `success_split`

布局目标：

让用户快速比较本轮输入图和生成图，并决定下一轮从哪张图继续。

主区域：

- 左右双栏等权展示。
- 左侧是本轮 source image。
- 右侧是本轮 result image。
- 两张图都显示编号。
- 两张图都可以点击选中，选中后可直接在该图上涂鸦。
- 支持两张图都不选中，恢复纯对比状态。

选中效果建议：

- 被选中图片外层显示 2px 主色描边。
- 被选中图片轻微放大，例如 `scale(1.015)`。
- 被选中图片阴影增强。
- 未选中图片不明显缩小，只轻微降噪，例如降低透明度或阴影。
- 被选中图片右上角显示“正在编辑”或笔刷图标。

下载按钮：

- 双图展示时，每张图片都应提供下载当前图片的按钮。
- 下载按钮建议放在图片卡片右上角或底部工具条中。
- 按钮使用下载图标，提供 `aria-label`，例如 `下载 #2`。
- 点击下载只下载被点击按钮所属图片，不改变选中状态。

控制区：

- 如果未选中任何图片，prompt 可以输入但发送按钮禁用，或提示“请选择要继续编辑的图片”。
- 如果已选中某张图片，prompt 非空时发送按钮可用。

### `error`

布局目标：

失败后不丢失用户上下文，允许快速恢复。

主区域：

- 左侧保留本轮 source image。
- 右侧显示失败原因、重试按钮和取消入口。
- 不产生新图片编号。

控制区：

- 保留 prompt。
- 保留涂鸦数据。
- 用户可以重试，也可以修改 prompt 后再次提交。

## 5. 每个按钮/手势的行为

### 上传图片

触发方式：

- 点击上传区域。
- 拖拽图片到上传区域。

行为：

- 校验文件类型。
- 创建第一张图片，编号为 `#1`。
- 设置 `currentSourceImageId = #1`。
- 进入 `editing`。

### 点击图片

触发方式：

- 在 `success_split` 中点击左图或右图。

行为：

- 将被点击图片设置为 `selectedSourceImageId`。
- 被选中图片显示选中态。
- 用户可以直接在该图片上涂鸦。
- 再次点击空白区域或当前选中图的取消选择入口，可恢复两图都不选中的纯对比状态。

### 涂鸦

触发方式：

- 用户在当前选中的图片上使用画笔。

行为：

- 记录标记数据。
- 不立即触发 API。
- 发送时导出真正的 mask data URL。
- 彩色涂鸦标记只用于页面展示，不作为 `input_image_mask` 直接提交。

### 发送 prompt

触发方式：

- 点击发送按钮。
- 输入框内按 Enter。

可用条件：

- 已有 source image。
- prompt 非空。
- 当前不在 `submitting` 或 `polling`。
- 在双图对比状态下，必须先选中一张图作为下一轮 source image。

行为：

- 锁定本轮 source image。
- 导出涂鸦标记。
- 进入 `submitting`。
- 创建图片编辑任务。
- 创建成功后进入 `polling`。

### minimap 切换版本

触发方式：

- 点击右上角版本树中的节点。

行为：

- 导航到对应版本节点。
- 根节点回到上传原图编辑态。
- 生成节点回到对应左右对比态。
- 节点内下载按钮只下载对应图片，不触发导航。
- 页面不使用鼠标滚轮切换版本；等待态、错误态和编辑态都不响应滚轮版本导航。

### 下载图片

触发方式：

- 点击图片上的下载按钮。

可用条件：

- 图片已成功存在。
- 图片有可下载 URL、base64 或可鉴权获取的资源路径。

行为：

- 下载按钮所属图片。
- 不改变 `selectedSourceImageId`。
- 不改变页面状态。

### 取消选择

触发方式：

- 点击空白区域。
- 或点击一个明确的取消选择按钮。

行为：

- 设置 `selectedSourceImageId = null`。
- 左右图片恢复等权对比。
- prompt 可保留，但发送按钮禁用，直到重新选择图片。

### 重试

触发方式：

- `error` 状态下点击重试。

行为：

- 使用同一 source image、prompt 和涂鸦数据重新提交。
- 不产生新编号，直到任务成功。

## 6. API 调用时机

### 创建图片编辑任务

触发状态/交互：

- `editing` 或 `success_split` 中选中图片后点击发送。

请求：

```text
POST /api/creation-tasks/image-edits
```

请求参数：

- `client_task_id`
- `image`
- `prompt`
- `input_image_mask`：仅当用户有涂鸦标记时传入，值必须是 `data:` 开头的图片 data URL
- `model`
- `size`
- `visibility`

mask 决策：

- 未涂鸦时允许提交，只传 `image + prompt`，不传 `input_image_mask`。
- 有涂鸦时，前端从涂鸦层导出与原图同尺寸的真正 mask 图，再以 data URL 传给 `input_image_mask`。
- 当前彩色圈选图不是 API mask。它可以继续用于 UI 展示或未来扩展为参考图，但第一阶段不混入真实请求。
- 后端 `responseImageMask` 只保留 `data:` 开头的 mask；普通远程 URL、ID 或非 data URL 会被忽略。
- 第一阶段固定 `n=1`，只处理 `task.data[0]`。

前端状态变化：

```text
editing/success_split
→ submitting
→ polling
```

成功响应：

- 返回任务对象。
- 记录 `taskId`。
- 开始轮询任务。

失败响应：

- 进入 `error`。
- 保留 source image、prompt 和涂鸦。
- 不产生新图片编号。

### 轮询任务

触发状态：

- 创建任务成功后进入 `polling`。

请求：

```text
GET /api/creation-tasks?ids=<taskId>
```

成功完成：

- 获取生成图片 URL、base64 或存储路径。
- 创建新图片对象。
- 分配下一个全局序号。
- 设置 `currentResultImageId` 为新图片。
- 进入 `success_split`。

失败完成：

- 进入 `error`。
- 不创建新图片。
- 不占用新编号。

### 取消任务

触发状态：

- `submitting` 或 `polling`。

行为：

- 调用真实取消任务 API：`POST /api/creation-tasks/{taskId}/cancel`。
- 成功后回到可编辑状态。
- 保留 source image、prompt 和涂鸦。

## 7. 错误、取消、重试

| 错误类型 | 出现时机 | 用户反馈 | 保留数据 | 编号规则 | 可执行操作 |
| --- | --- | --- | --- | --- | --- |
| 上传失败 | 文件读取或格式不支持 | 显示上传失败原因 | 不创建图片 | 不产生编号 | 重新选择 |
| 涂鸦导出失败 | 点击发送后导出标记失败 | 显示标记导出失败 | 图片、prompt、已知标记 | 不产生编号 | 重试或清除标记 |
| 提交失败 | 创建任务 API 失败 | 显示提交失败 | source image、prompt、涂鸦 | 不产生编号 | 重试、修改 prompt |
| 生成失败 | 任务返回 error | 显示生成失败原因 | source image、prompt、涂鸦 | 不产生编号 | 重试、取消 |
| 任务超时 | 轮询超过限制 | 显示等待超时 | taskId、source image、prompt | 不产生编号 | 继续等待、取消、重试 |
| 用户取消 | 用户主动取消任务 | 显示已取消或返回编辑 | source image、prompt 可保留 | 不产生编号 | 继续编辑 |

原则：

- 错误不清空用户上传的图片。
- 错误不清空 prompt。
- 错误不清空涂鸦数据，除非用户明确清除。
- 失败任务不创建图片对象，不占用序号。

## 8. 第一阶段实现范围

阶段名称：

Retouch 主路径与双图对比交互。

本阶段目标：

把现有 mock 生成流程整理为真实的“上传 → 涂鸦 → 发送 → 等待 → 左右对比 → 选择图片继续编辑”主路径。

包含范围：

- 上传图片并登记为 `#1`。
- 顶部显示图片编号列表。
- 初次图片涂鸦与 prompt 输入。
- 点击发送后进入双栏等待态。
- 右侧等待区显示 spinner 和已等待时间。
- API 成功后创建新图片编号并展示左右对比。
- 双图都可点击选中。
- 选中后直接在对应图片上涂鸦。
- 双图展示时支持下载当前图片。
- 失败时不创建新编号，保留上下文并支持重试。

不包含范围：

- 树状 minimap 的高级自动布局、缩放和复杂动画。
- 多任务并发。
- 批量结果。
- 复杂历史动画。
- 图片版本重命名。

涉及文件/模块：

- `web/src/pages/EditorPage.tsx`
- `web/src/store/useImageTreeStore.ts`
- `web/src/lib/api.ts`
- `web/src/app/retouch/components/retouch-canvas.tsx`

验收标准：

- 初次上传图片后显示编号 `#1`。
- 点击发送后，页面进入左图 source image、右侧等待状态。
- 等待状态显示 spinner 和已等待时间。
- 成功后右侧显示真实生成图，并分配下一个编号。
- 点击左图或右图能看到明确选中态。
- 选中某张图后可以继续涂鸦并再次发送。
- 下载按钮可以下载所属图片，且不改变当前选中状态。
- 失败时不新增图片编号，prompt 和涂鸦保留。

验证命令：

```text
cd web && npm run build
cd web && npm run lint
```

## 9. 当前实现进度

更新时间：2026-06-29

当前实现仍处于 mock 生成阶段，目标是先把 Retouch 主路径和状态模型跑顺，再接入真实图片编辑任务 API。

已完成：

- 上传图片后创建第一张图片，并显示全局编号 `#1`。
- `useImageTreeStore` 维护 `nextImageNumber`，只有成功生成的新图片才分配新编号。
- 页面已有明确的状态字段 `pageStatus`，覆盖 `empty`、`editing`、`polling`、`success_split`、`error` 等主路径状态。
- 第一次发送 prompt 后，页面进入双栏等待态：左侧显示本轮 source image，右侧显示 spinner 和已等待时间。
- mock 生成成功后创建一张新的结果图，并分配下一个编号，例如 `#2`。
- 成功后进入双栏对比态，左侧显示本轮输入图，右侧显示本轮结果图。
- 双栏中左图和右图都可以点击选中，选中后显示蓝色描边和“正在编辑”标记。
- 选中某张图后，可以直接在该图上涂鸦并输入下一轮 prompt。
- 第二轮发送时，刚刚选中的图片会立即变成本轮左侧 source image，右侧显示等待区和计时，行为与第一轮发送一致。
- 初次上传图片和选中态涂鸦均保持等比例画布显示，避免图片裁切和笔触坐标偏移。
- 中间双栏工作区已放大，减少与顶部导航和底部输入框之间的空白。
- 双栏中左图和右图都已提供下载按钮，下载不会改变当前选中态。
